Python Shellcode Loader

Tests EDR/AV detection of Python-based shellcode injection using ctypes for memory allocation, shellcode copying, and thread execution — techniques used by APT29's SeaDuke and the Donut framework.

📋 Overview

This test evaluates whether your security solution can detect when Python is used to inject and execute shellcode in memory. The technique leverages Python's ctypes library to call Windows API functions directly, bypassing traditional executable-based detection.

Adversaries use this technique because Python scripts are often trusted by security solutions, and the actual malicious code (shellcode) only exists in memory, making it harder to detect through file-based scanning.

🔍 Detection Opportunities

API Call Monitoring

Python.exe calling VirtualAlloc with PAGE_EXECUTE_READWRITE (0x40) permission flag

Memory Analysis

RWX memory regions allocated by python.exe process that weren't present at startup

Thread Creation

CreateThread called with start address pointing to recently allocated memory

Behavioral Pattern

Sequence: VirtualAlloc → memory write → CreateThread within short timeframe

🎯 What This Test Validates

  • Memory protection monitoring — Can EDR detect RWX memory allocation from scripting interpreters?
  • API hooking effectiveness — Are VirtualAlloc/CreateThread calls from Python properly monitored?
  • Behavioral detection — Does the EDR correlate the injection pattern across multiple API calls?
  • Process context awareness — Is Python treated differently than compiled executables?
